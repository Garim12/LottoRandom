# 행운번호 생성기

로또 6/45와 연금복권 720+ 번호를 브라우저에서 무작위로 생성하는 모바일 우선 웹앱입니다. [GitHub Pages](https://garim12.github.io/LottoRandom/)에서 사용합니다.

## 기능

- 로또 1·3·5게임 생성, 개별/전체 재생성, 완전 중복 조합 방지
- 로또 번호 최대 6개 고정 및 번호 제외
- 로또 기본 무작위 / 게임 간 분산 선택: 고정·제외 조건을 지키며 덜 사용한 번호부터 선택, 개별 재생성에도 적용
- 로또 조건 생성: 합계 범위, 홀짝 비율, 최장 연속 번호, 최소 사용 구간 설정 및 분산 생성 병용
- 조합 분석: 게임별 합계·홀짝·최장 연속·5구간 분포와 전체 게임에서 사용한 서로 다른 번호 수 표시
- 로또 10가지 전략 선택, 실제 회차의 빈도·미출현 통계, 로컬 모델 학습·시간 순서 검증·커스텀 가중치
- 연금복권 낱장과 동일한 6자리 번호의 1~5조 세트 생성, 부분 재생성
- 연금복권 분산 5장: 서로 다른 끝자리로 생성, 묶음 복사·저장·기록·불러오기
- 번호 복사, 저장 번호, 최근 기록 30개, 불러오기와 삭제
- 시스템 설정을 따르는 라이트/다크 모드 및 접근 가능한 모바일 UI

번호는 Web Crypto API의 `crypto.getRandomValues()`로 생성합니다. `randomInt()`는 rejection sampling으로 modulo bias를 피합니다. 번호 생성에는 `Math.random()`을 사용하지 않습니다. 저장 번호와 기록은 서버로 보내지 않고 사용 중인 브라우저의 `localStorage`에만 보관됩니다. 저장 형식은 `version: 1`을 사용하며 손상된 데이터는 안전하게 기본값으로 복구합니다.

분산 생성은 당첨 확률을 높이는 기능이 아닙니다. 로또 분산은 게임 간 번호 겹침을 줄이며, 1게임에는 분산 효과가 없고 고정·제외 조건에 따라 겹침이 생길 수 있습니다. 전체 게임의 최적 조합을 보장하지 않습니다. 연금복권 분산은 끝자리 5개를 중복 없이 뽑고 각 장의 조와 나머지 5자리를 무작위로 생성합니다. 같은 장수에서 1등 확률이나 기대 당첨금이 증가하지 않으며, 판매처에서 해당 번호를 구매할 수 있는지는 별도로 확인해야 합니다. 기존 저장 데이터와 함께 분산 5장도 `version: 1` 형식으로 보관됩니다.

## 기술 스택

Vue 3 Composition API, TypeScript, Vite, Tailwind CSS, Lucide Vue Next, Vitest, GitHub Actions, GitHub Pages. 라우터와 서버는 사용하지 않습니다.

## 조건 생성과 조합 분석

`조건 생성`에서 합계(21~255), 홀수 개수(0~6 또는 제한 없음), 허용하는 최장 연속 길이(1~6), 최소 사용 구간(1~5)을 고릅니다. 구간은 번호 공 색상과 같은 1~10 / 11~20 / 21~30 / 31~40 / 41~45입니다. 고정·제외 번호가 우선 적용되며, 개별 및 전체 재생성에도 조건이 적용됩니다. `게임 간 분산 함께 사용`으로 번호 사용 빈도도 고려할 수 있습니다. `균형 조건 예시`는 합계 100~175, 홀짝 3:3, 최대 2연속, 최소 3구간을 설정하는 취향 예시입니다.

조건 생성은 무작위 후보 순서를 탐색하고, 합계·홀짝·구간 조건상 불가능한 경로를 미리 제외합니다. 조건을 만족하는 모든 조합을 균등하게 추출하는 방식은 아닙니다. 동기 탐색은 게임당 50,000개 노드로 제한하여 과도한 계산을 막고, 한도에 도달한 경우와 가능한 조합이 부족한 경우를 다른 오류로 안내합니다. 실패하면 화면의 기존 번호와 생성 기록은 유지됩니다. 더 큰 탐색이 필요해지면 Web Worker로 옮길 수 있습니다.

`조합 분석 보기`는 현재 표시된 번호를 직접 계산합니다. 저장 번호를 불러온 뒤에도 분석할 수 있습니다. 합계의 이론 평균 138은 `6 × (1 + 45) / 2`이며 예측 점수나 신뢰도가 아닙니다.

참고: 사용자가 제공한 [연속 번호 필터 글](https://npackgames.tistory.com/74), [분석 전략 소개](https://npackgames.tistory.com/157), [합계 분포 글](https://npackgames.tistory.com/173)의 주제를 참고하고 TypeScript로 직접 구현했습니다. 글의 코드·이미지·실험 결과 수치는 복제하지 않았으며, 합계의 정규분포 근사는 개별 조합의 당첨 확률 증가를 뜻하지 않습니다. [트랜스포머 평가 후속 글](https://npackgames.tistory.com/185)에서 다룬 표본·난수 문제를 고려해 확인되지 않은 신뢰도나 AI 예측 점수를 표시하지 않습니다.

## 10가지 전략

블로그에 소개된 주제를 바탕으로 아래 규칙을 직접 정의했습니다. 원 서비스의 비공개 엔진을 복제한 구현은 아닙니다. `10가지 전략`에서 선택하며, `조건 생성`의 수동 필터와는 별도 모드입니다. 고정·제외 번호, 1·3·5게임, 완전 중복 방지, 개별 재생성은 모든 전략에 적용됩니다. 전략 조건과 고정·제외 번호가 충돌하면 기존 결과를 유지하고 오류를 표시합니다.

| 전략 | 실제 동작 |
| --- | --- |
| 랜덤 생성 | 기존 Web Crypto 기반 균등 추출 |
| 빈도 균형 | 출현 횟수로 정렬한 상위·중간·하위 15개 번호에서 각각 2개, 동률은 번호순 |
| 구간 분산 | 공 색상 기준 5구간에서 각각 최소 1개 |
| 패턴 유사성 | 선택 기간의 최빈 홀짝 비율 |
| 머신러닝 | 과거 회차로 학습한 로지스틱 회귀의 출력을 번호별 추출 가중치로 사용 |
| 연속 미출현 | 기간 내 연속 미출현 횟수 + 1을 추출 가중치로 사용 |
| 당첨 패턴 | 최빈 홀수 개수·저번호(1–22) 개수·최장 연속 길이 묶음. 앞의 두 개수는 정확히 맞추고 연속 길이는 상한으로 적용 |
| 황금비율 | 피보나치 수 1·2·3·5·8·13·21·34에서 정확히 2개를 고르는 취향 규칙 |
| 합계 범위 | 선택 기간의 합계 20~80백분위(하한 내림 인덱스, 상한 올림 인덱스) |
| AI 커스텀 | 로컬 모델·빈도·미출현·피보나치 선호를 0~10 가중치로 혼합. 외부 LLM/API 호출 없음 |

최근 100회·300회·전체 중 분석 기간을 선택합니다. 빈도는 보너스 번호를 제외한 6개 번호로 계산하며, 기간 내 미출현 번호의 갭은 해당 기간 이상이라는 하한입니다. 최빈 패턴 동률은 문자열 오름차순으로 결정합니다. 번호 가중치는 지수 난수 키로 비복원 추출 순서를 정합니다. 커스텀에서는 각 항목을 해당 항목의 최댓값으로 정규화해 가중 평균하고 모든 번호에 0.05를 더합니다. 선호도가 없는 번호도 선택 가능하며, 조건 탐색·중복 회피로 인해 모든 허용 조합이 균등하지는 않습니다.

로컬 모델은 각 번호의 직전 20회 빈도, 최대 직전 100회 빈도, 미출현 길이(최대 60회), 직전 출현 여부를 입력으로 사용합니다. 초기 20회는 입력 준비에만 쓰고, 이후 회차의 번호별 출현 여부를 정답으로 학습합니다. 절편을 제외한 L2 정규화 0.01, 학습률 0.2, 40회 배치 경사하강을 사용합니다. 화면의 시간 순서 검증은 대상 회차의 앞선 80%로 한 번 학습하고 이후 20%를 평가합니다. 검증 회차마다 입력에는 그 이전까지 공개된 결과만 반영하며 검증 구간에서 모델을 재학습하지 않습니다. 검증값은 상위 6개 번호의 평균 일치 개수이고, 균등 무작위의 이론 평균은 `6 × 6 / 45 = 0.8`개입니다. 실제 가중 무작위 생성이나 커스텀 혼합 전체의 검증값은 아닙니다. 생성용 모델은 선택 기간 전체로 다시 학습하며 미래 성능 우위는 주장하지 않습니다.

### 당첨 이력 갱신

`src/data/lotto-history.json`에는 [동행복권 당첨 결과](https://www.dhlottery.co.kr/lt645/result)에서 수집한 1~1244회(2026-10-03) 이력이 포함되어 있습니다. 출처·수집 시각·회차·추첨일을 함께 기록하고 연속 회차, 실제 날짜, 1~45 번호 6개와 중복 여부를 검증합니다. 브라우저에서는 배포에 포함된 이력만 사용하므로 CORS나 외부 API 장애 없이 작동합니다. 자동으로 최신 회차를 가져오지는 않습니다.

```sh
npm run data:update
npm test
npm run build
```

갱신 명령은 동행복권 결과 화면이 사용하는 공개 조회에서 새 회차만 추가하며, 최초 실행은 전체 이력을 수집합니다. 원본 누락·형식 변경·네트워크 오류가 있으면 실패하고 기존 JSON을 보존합니다. 갱신한 JSON을 커밋하고 배포해야 사이트에 반영됩니다. API 키, 서버, 추가 런타임 의존성은 필요하지 않습니다.

## 개발

Node.js 24 이상과 npm이 필요합니다.

```sh
npm install
npm run dev
```

검증 및 production 미리보기:

```sh
npm run test
npm run typecheck
npm run build
npm run preview
```

`npm run preview`의 기본 로컬 주소에서 `/LottoRandom/` 경로를 열어 빌드 결과를 확인합니다.

## 배포

Vite의 `base`는 `/LottoRandom/`입니다. `main`에 push하면 `.github/workflows/deploy.yml`이 `npm ci` → 테스트 → 빌드 → 공식 Pages artifact 업로드 → 배포를 실행합니다. GitHub Repository의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정해야 합니다. 배포 주소는 `https://garim12.github.io/LottoRandom/`입니다.

## 구조

`src/components/common`은 탭, 테마, 알림, 보관함 UI를 담고, `src/components/lotto`와 `src/components/pension`은 각 생성기 UI를 담습니다. `src/utils`에는 Vue와 분리된 난수·생성·복사 로직이 있고, `src/composables`에는 테마·알림·저장소 로직이 있습니다. `src/types`는 공유 타입을 정의합니다.

## 책임 있는 이용

이 사이트는 무작위 번호 생성 도구입니다. 당첨 번호를 예측하거나 당첨을 보장하지 않으며, 모든 번호 조합의 당첨 가능성은 동일합니다. 미성년자는 복권을 구매할 수 없습니다.
